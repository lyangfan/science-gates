# Science Gates

**把科学问题或分析草案，变成有明确验收标准、真实执行证据和完整 HTML 报告的工作流程。**

适用于实验设计、数据分析、已有结果核查等科研任务，可跨项目复用。它将用户的科学决定、
agent 的实施工作和独立审查分开，并用脚本检查容易遗漏的字段、样本、依赖和证据。
当前版本为 **1.1.0 / SCI v12**；agent 入口是 [SKILL.md](SKILL.md)，ENG 单独维护。

## 从哪里开始

典型起点是一份 `spec_draft.md`，也可以是科学问题、讨论记录和几份已有材料。
草案不必完整，但需要逐步明确：**要回答什么、用哪些对象和数据、怎样判断结果是否成立**。
项目路径、执行主机、数据权限和输出位置按实际任务补齐，不预设某个项目的配置。

| 你已有的材料 | 从哪里进入 |
|---|---|
| 科学问题、讨论记录或草案 | 整理决定与未决项，形成正式 spec，进入门 A |
| 已冻结 spec，且有有效门 A PASS | 核对版本和许可后进入门 B |
| 已有结果，需要审查、补证或完善报告 | 读取当前合同与审查记录，只处理授权范围；不自动重跑实验 |

下面是新任务走完一条 SCI 链的主流程。只要求整理 spec 时，工作停在相应阶段。

```mermaid
flowchart LR
    START["起点<br/>科学问题 / 草案"] --> A["门 A<br/>审科学合同"]
    A -->|通过| BPRE["门 B · 执行前<br/>审实现与启动条件"]
    BPRE -->|放行| RUN["执行 / 复用<br/>保留真实证据"]
    RUN --> BPOST["门 B · 结果<br/>审结果与 HTML"]
    BPOST -->|通过| DONE["交付<br/>报告与证据"]

    classDef input fill:#f1f5f9,stroke:#94a3b8,color:#243746;
    classDef gate fill:#e5f3f1,stroke:#137b80,color:#164b50;
    classDef output fill:#fff4df,stroke:#b68a3d,color:#654b20;
    class START,RUN input;
    class A,BPRE,BPOST gate;
    class DONE output;
```

图中展示通过路径；有问题时按预算定向修复和复核，未解决的阻塞不会随阶段推进而消失。

## 门 A：方案是否明确、可执行、可验收

门 A 审查的是**科学合同**。它把“想做什么”写成实施者能够遵循、Reviewer 能够核查的要求。
下表 A1–A6 是审查项编号，具体实验另行编号。

| 检查 | 要回答的问题 |
|---|---|
| A1 决策保真 | 用户已确认的决定是否完整落地？有没有把未决写成已定，或恢复已取消的方案？ |
| A2 事实与约束 | 数据字段、数量、路径、主机、工具行为是否有依据，并符合项目规则？ |
| A3 未决与授权 | 样本、方法、阈值等科学选择是否明确？工程自主范围、人工检查点和停止条件是否清楚？ |
| A4 验收可证 | 每个结果和禁止事项有没有可观察的检查？错误实现是否真的会被检查挡住？ |
| A5 输入与写入范围 | 输入来源、键、单位和版本是否明确？哪些代码可改、产物写哪里、怎样保护历史文件？ |
| A6 内部一致 | spec、验收合同和有效修订中的样本集合、计数、阈值与阶段是否相互一致？ |

通过后固定：**正式 spec、决定落点、机器可读验收合同、关键错误反例、工程授权与运行计划、
HTML 报告要求**。spec 供人理解，机器合同供脚本逐项核验；实施者不能临时删减必需验收。

例如，“跨三个 seed 汇总体积绝对误差”必须明确先取绝对值还是先平均。
门 A 固定用户选择的顺序，门 B 再检查代码、结果和报告是否遵循该顺序。
**写出 spec 文件本身不等于门 A PASS**，还需要独立审查及固定版本的记录。

## 门 B：实现、真实结果和科学结论是否符合合同

门 B 有两个审查阶段，中间才是获准的科学执行。

| 阶段 | 主要审什么 | 通过意味着什么 |
|---|---|---|
| **执行前审查** | 代码是否忠实实现 spec；验收器是否能识别错误；真实主机上的路径、字段、样本键、环境、输入供应、权限和输出冲突是否检查充分 | 所列版本和范围可以执行，未来结果仍待审 |
| **结果审查** | 实际方法、运行记录和结果是否对应；样本是否完整；分母、顺序、单位和方向是否正确；HTML 数字、图表、结论与文献支持是否一致 | 完整必需验收满足后，才能建立门 B PASS |

两阶段共同遵循四项原则：**B1 规范保真、B2 验收证据、B3 叙述＝数据＝实做、B4 上下游合同一致**。
执行前尚未产生的科学结果不能提前判通过；“文件存在”“行数正确”“作业成功”也不能单独证明科学正确。

审查分别回答三件事：

- **完整性**：要求的分析、样本和证据是否齐全，有没有遗漏、重复或不当排除。
- **科学正确性**：方法与统计是否符合合同，结论强度是否受到实际结果支持。
- **执行身份**：这些结果是否对应受审的代码、输入、参数和真实运行。

## 谁负责决定，谁负责审查

| 角色 | 职责 |
|---|---|
| 用户（Decision Owner） | 确认影响结果的科学选择、接受限制，以及超预算和发布决定 |
| 协调者（Coordinator） | 整理合同、准备交接、运行机械检查、登记审查与版本 |
| 实施者（Implementer） | 按合同实现、执行和修复，保存原始命令、日志与产物 |
| 独立审查者（Reviewer） | 在独立上下文中核对合同与证据，判断方法和结论是否成立 |

各角色可以使用不同模型。批准范围内的路径接线、CLI、资源和有限重试由实施者自主处理并留痕；
影响样本、方法或结论范围的变化仍由用户确认。Reviewer 不审自己的实现，脚本的
`MECHANICAL_OK` 也不等于科学 PASS；独立性需要实际的角色与上下文安排。

## 最后交付什么

**每条新 SCI 链默认必须交付一个覆盖完整 spec 的 HTML 科学报告，即使草案没有提到 HTML。**
门 A 就确定报告范围，门 B 生成并审查报告。每个分析说明：

> 实验目的 → 实际方法与样本 → 结果与可视化 → 科学结论 → 局限与来源

完成的分析关联现有代码、输入清单、实际命令和运行记录。未执行、取消或证据不足的部分保留说明，
不因缺结果删掉章节。最终报告核查六项：**范围、方法、数字、图表、结论、来源**；
只有审计状态、没有实质结果的页面不算完成报告。本地生成报告不自动授权公开发布。

## 怎样控制时间和计算成本

- **科学计算默认一次。** 独立审查核代码、原始运行材料和已有结果，不默认再算统计量、P 值、
  训练、预测或 GWAS。保留将来复现的材料，但不声称已经独立复现。
- **先查便宜的问题。** 路径、环境、键和输出冲突先检查；大输入只按实际消费范围核验，
  审查引用当次记录，不每轮重新扫描整棵数据目录。目录 metadata 巡检不冒充内容哈希证明。
- **修复只审受影响部分。** 门 A 首审后最多一次增量修复复核；门 B 执行前、结果审查各最多两次。
  未变部分只能引用对象、依赖和适用范围均相同的直接 PASS 证据。

需要额外重算或读取大数据时，先说明范围、必要性和预计成本，由用户决定。
预算用尽仍有阻塞时停止受影响步骤，新增轮次须获准；缺证据仍是缺口，不能为了省时改成“不适用”。

## 开始使用与进一步阅读

把整个仓库作为一个 skill 目录提供给支持 `SKILL.md` 的 agent，或在任务中给出其绝对路径。
安装与自动发现方式由 agent 宿主决定。一个从草案开始的请求可以是：

> 请按 `/path/to/science-gates/SKILL.md` 处理当前项目。上游是 `docs/spec_draft.md`。
> 本轮先整理正式 spec 并完成门 A；科学选择按影响顺序提出，不运行实验。

首次按 [项目接入](references/project-setup.md) 登记实际配置并固定 skill 版本；
进行中的旧链按明确批准的范围迁移，升级不会自动重写旧 spec、结果或 PASS。

| 想进一步了解 | 阅读入口 |
|---|---|
| 完整规则与放行条件 | [SCI 协议](references/protocol.md) |
| 门 A / 门 B 的具体操作 | [门 A](references/gate-a.md)、[门 B](references/gate-b.md) |
| HTML 内容、模板与核查 | [报告规范](references/report.md) |
| 脚本参数、数据格式与文件身份 | [工作流格式](references/workflow-schema.md)、[摘要与目录巡检](references/digests-and-snapshots.md) |
| 工具验证与脚本来源 | [验证记录](validation/README.md)、[来源清单](references/source-provenance.json) |

脚本需要 Python 3.10+，使用标准库；Git / SSH 仅在对应核验中使用。
`scripts/science.py` 提供生成交接材料、检查、执行明确步骤和转录独立审查判定的入口，
`scripts/report.py` 生成并核查离线报告。仓库仅保留一套当前脚本，历史实现由 Git 保存。

在本 skill 仓库根目录可运行：

~~~bash
python3 scripts/run_tests.py
python3 scripts/make_example.py --out /tmp/science-gates-demo
~~~

第二条要求目标目录不存在；生成合成数据、合同、工作流材料及可离线打开的 `demo.html`。
示例用于理解流程，数值不是真实科学结论。
