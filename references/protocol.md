# SCI PROTOCOL v11.0-sci（science-gates 1.0.1）

> 门 A 冻结可执行的科学合同；门 B 实现、验证并由独立审查建立结论。严格约束科学语义，工程动作在明确授权内自主处理。机器核验通过不等于科学 PASS。

## §0 适用范围与迁移

- 用户要求整理上游时：核清决策，形成 spec，再走门 A。要求实施冻结 spec 时：核门 A 的有效 PASS 后走门 B。不确定任务所处阶段时先读本链账本，不靠文件存在推定通过。
- 上游可以多份，每份有路径和 SHA256。链名在首次派发时确定；工件根仍为 `runs/<chain>/reviews/<A|B>/`，科学产物仍在链内独立 attempt。
- 本协议只规范 SCI；ENG 由独立 skill 维护。工程授权不得改变工作区的大文件、敏感数据、稿件编辑或发布规则。
- 新链使用本版。已有链只有在用户批准的修复/迁移范围内使用本版；旧 spec、PASS、报告、快照与原始产物不回写。协议升级不追溯否定旧协议的历史记录，也不能把历史记录当成新版检查已经执行的证据。
- 已冻结 spec 的机器可读合同可旁置补录：逐项映射原条款和已有用户裁定，由独立 Reviewer 核语义等价；不修改原 spec，不补造旧运行事实。新增科学语义仍须用户确认及门 A 增量审查。
- 约定层槽位：远端主机及只读取法、调度器及记录取法、冻结资产清单、对外发布面、统一产出入口。槽位取值写入已认证合同；实际需要但缺失时记 `NOT_VERIFIABLE`，不能临场猜测。
- 外部数据及大型产物保留原位置。可入库代码、合同、派发、审查、原始核验日志进入 Git；禁止复制敏感/大文件到 reviews 绕过工作区规则。

## §1 核心约束与预算

1. **科学要求有独立权威。** 门 A 冻结 spec 与验收合同。验收合同列全部验收及禁止事项、对应条款、适用阶段、必需角色、键、字段、单位、核验方式和允许例外。阶段 manifest 只能引用，不得自行缩减要求。编号覆盖不能替代语义审查。
2. **完整性、科学正确性、执行身份分别核验。** 文件身份、行数、来源字符串、DONE、作业成功及摘要一致，均不能单独证明科学计算正确。
3. **有限增量修复。** 门 A 保持一次 Baseline（b1）加一次 Closure（c1）。门 B 执行前为 b1，最多两轮增量修复 r1/r2；结果审查为 c1，最多两轮增量修复 c2/c3。两阶段分别计数，不相互借用、不因改名或用户回答问题清零。超预算须用户批准；用尽仍有阻塞则记 `NON_CONVERGENT` 并停止受影响步骤。
4. **增量范围可追溯。** 复核上轮开放 finding、实际修改、必要依赖及回归。未变部分仅继承直接 PASS，且输入、实现、依赖和适用范围均须相同。FAIL、NA、NOT_VERIFIABLE、准备阶段合成测试不能继承为新增科学结果 PASS。
5. **真实阻塞不能藏入 notes。** 后发现的问题只要能引用既定要求，就纳入受影响单元的复核并阻止错误结果放行；纯新增需求和风格偏好不能冒充既定要求。无需因此重审全部 Baseline。
6. **PASS 绑定对象及阶段。** 记录固定提交、合同、受审代码、直接依赖、真实产物与证据身份。字节或科学依赖改变后，旧 PASS 不覆盖变化部分。执行前通过只授予执行许可；补证范围通过不等于整链通过。

## §2 角色、授权与读取面

| 角色 | 职责 | 边界 |
|---|---|---|
| Decision Owner（用户） | 科学决策、工程授权范围、超预算、接受限制、对外发布 | 不把模糊的“自行处理”解释为改变样本、方法或结论范围 |
| Coordinator | 编制合同/阶段 manifest，机械预检、派发、记录与 Git 保全 | 不冒充独立 Reviewer，不手填摘要，不以自检建立科学 PASS |
| Implementer | 按合同实现、执行、修复并留原始证据 | 不弱化验收、不修改冻结科学输入、不凭缺文件推断 NA；不得担任自身实现的 Reviewer |
| Reviewer | 独立核对合同、实现、原始证据和真实结果，提交不可变报告 | 不参与修复、不提交科学作业、不写正式科学产物、不替用户作科学选择 |

**科学决策与工程授权**：样本、分组、方法、阈值、统计、证据纳入范围和结果影响的参数由用户确认。门 A 可一次批准代码/输出范围、接口接线、命名规则、主机资源范围、日志和有限重试。范围内工程决定由实施者留痕执行，不逐个请示 CLI。未获准的范围扩展或科学歧义先停受影响步骤，不依赖它的工作继续。

工程授权不能豁免明确的人工采用点、下载决定、敏感数据规则和发布决定。Reviewer 的修复建议仅为建议；与既定合同冲突时以合同为准，记录冲突并修订建议，不能机械执行错误 closure。

读取面由已认证阶段 manifest 的对象及直接依赖明确给出。科学输入、候选、依赖、产物、证据、权威文件分角色；只读对象不能通过改角色解冻。当前 Implementer 在获准写入面生成的文件可继续读取，但交付必须登记，Reviewer 消费前也必须进入 manifest。

允许在已列对象的父目录进行轻量列名/属性探测，不因此获得任意内容读取权限。未知必需依赖记缺口；已授权工程范围内的补列经机械核验并重新绑定本阶段材料，不能悄悄扩大科学输入。读取越界必须如实报告。

Reviewer 从独立上下文启动，只接收中性的派发、固定对象和前序直接证据，不接收 Coordinator 的倾向或答案。辅助验证只读正式对象，临时输出限 `/tmp` 或明确独占的审查证据位置；不得提交调度器作业、修改受审文件、推送镜像或执行 VCS 写操作。

修复保持同一 Implementer 的责任与上下文；增量审查优先同一 Reviewer。确需更换时移交固定材料，不继承无证据的结论。科研证据和 HTML 默认中文，可按用户指定语言；原文引句保留原语言。

## §3 finding 与审查报告

| 严重度 | 含义 | 阻塞 |
|---|---|---|
| BLOCKER | 违反科学权威，产生错误/不安全结果，或正确执行必然无法开始 | 是 |
| MAJOR | 规范保真、真实验收、科学叙述或上下游合同存在实质缺口 | 是 |
| MINOR | 不影响科学结果和证据可验证性的组织、编号、表述缺陷 | 否，登记 owner |
| OPINION | 不属于既定要求的风格或替代设计 | 否 |

finding 包含 `id/check/severity/location/excerpt/authority/counterexample/closure`。严重度由 Reviewer 判断。字段不完整则报告不合格，原 Reviewer 补证；**不得因格式不齐自动降低真实问题的严重度**，补不齐的实质问题保持未验证状态，不能靠格式缺陷放行。

同一根因合并；closure 写明违例、需要恢复的行为与可验证关闭条件，可附修复建议。修复后既要击败原反例，也要核受影响不变量，尤其标签与文件名、主机与路径、预留目录与创建者等不同概念。

未决科学语义单列问题和依赖，不凭它推定其它检查通过。判定优先级：开放 BLOCKER/MAJOR → FAIL；必需项不能验证 → NOT_VERIFIABLE；仅剩用户科学决定 → NEEDS_USER_DECISION；其余按本阶段完成条件判断。

报告正文保留判断、定位和边界；同时提供结构化检查项、finding、未决事项和证据引用。原始输出保存为文件并引用身份，禁止改写摘要后标“原始输出”。`record` 仅核结构和转录，不能替 Reviewer 判科学成立或接受限制。

## §4 门 A：形成可执行合同

| ID | 必查内容 |
|---|---|
| A1 决策保真 | 上游全部当前有效决定逐条、语义等价落地；历史推翻项不复活、未决不写成已定 |
| A2 外部约束与事实 | 工作区政策、实际输入字段/路径/主机、数据计数、工具行为与已核事实一致 |
| A3 未决与工程授权 | 科学选择唯一；工程范围可执行；未来人工检查点有材料、负责者和停止条件 |
| A4 验收可证 | 每个结果及禁止事项都有能击败错误实现的检查；必需全集独立冻结，不能同时删除检查和期望而假绿 |
| A5 输入与写入面 | 权威文件及字段、键、单位、主机与身份明确；候选可修改范围、输出创建归属、历史保护与 no-clobber 明确 |
| A6 内部一致 | 全文与机器合同的集合、计数、阈值、阶段、命名及有效修订一致 |

门 A 的交付包括：

1. 正式 spec 与上游决定落点表。未编号上游可说明理由用人工语义核查，不编造零项覆盖 PASS。
2. 旁置的机器可读验收合同：每条要求及其细分断言的固定 ID、规范定位、输入角色及语义、键/字段/单位、输出、允许空集、阶段适用性、验收方法和证据类型。
3. 关键反例与其预期结果。准备阶段只测试接口、合成边界和真实运行条件，不提前取得待审科学结果。验收器可作为版本化的只读基准；后续改动须审其是否放宽断言。
4. 工程授权与运行计划：执行主机、依赖、输出创建者、资源范围、重试上限、进度及人工检查点。外部检索先核 API/来源语义、返回层级、查询规模和预算；降级或筛选会改变证据范围时由用户确认。

5. HTML 报告合同：固定分析 ID 全集、逐项目的/方法/样本/结果/结论/局限及可视化适用性，报告内容进入最终独立验收。机器格式见 report.md。

大型文件清单放在已认证 manifest，不在正文和每份审查报告反复抄写。机器逐项查清单；模型阅读规范语义与差异。科学输入和只读依赖冻结，候选只登记每次交接的起始/受审字节；尚不存在的产物标 planned，不填虚构摘要。

门 A PASS 须 A1–A6 全部通过或有依据的不适用、无开放阻塞/未决、机械核验通过及独立审查报告入库。状态在账本，不回写被冻结 spec 的头部。机器可读合同与 spec 一起绑定；不能在 c1 才定义“必须检查什么”。

科学修改回写上游，明确新增、替代和撤销关系；对受影响条款及依赖做门 A 增量审查。旧科学条款保持可追溯。执行期用户裁定形成追加修订清单，带原始依据、条款、适用阶段和审查状态，生成当前有效视图；批准科学选择本身不代替执行许可。

## §5 门 B：准备、执行与结果审查

| 阶段 | 工作 | 放行条件 |
|---|---|---|
| 准备 | 按冻结合同实现候选和验收器；真实主机轻量预检、合成反例、输出计划检查 | 机械预检全绿才派发 |
| b1；必要时 r1/r2 | 独立核实现、验收强度、接口、真实输入路由、权限及停止条件 | B1/B4 通过；B2/B3 科学结果部分暂 NA；只授执行许可 |
| 科学执行 | 按放行代码和已满足人工条件执行，保留失败和成功记录 | 字节、范围、检查点符合许可 |
| c1；必要时 c2/c3 | 核新增真实结果、完整验收、叙述和执行身份 | 满足完整合同及下表才记门 B PASS |
| 明确授权的补证 | 对既有结果独立复核，版本化新增证据，不追认缺失历史事实 | 仅对声明范围作结论，未覆盖项继续待验 |

| ID | 必查内容与失败条件 |
|---|---|
| B1 规范保真 | 所有科学条款及禁止项真实落在正式执行路径；漏维度、改顺序、缩范围、只在测试存在、写入越界或弱化验收均不通过 |
| B2 验收证据 | 从门 A 冻结全集核每项及细断言；真实边界、实际字节、完整键集和数值检查已执行；空表、跳过、恒真、同源自证或行数替代不得通过 |
| B3 叙述=数据=实做 | 每个结论数字、对象、方向、状态及上下游丢弃记账与真实证据相符；“已完成”的范围不得大于实做；原始输出不可被改写冒充 |
| B4 上下游合同 | 实际生产/消费的 schema、键、单位、词表、主机、输出路径及失败语义一致；缺失不静默变空集，不把标签和产物命名混为一项 |

**结果复核与身份绑定**：确定性表格/统计默认全量独立复算，按合同规定精度比较；抽样只在 spec 预先指定对象、方法和范围时可用。生产函数不得同时作为唯一参考答案。大计算可用执行者不可修改的调度/CI记录加当时代码摘要核执行身份，但仍须有实质科学断言、方法和边界证据；执行发生在远端不是不能复算的理由。无法获得规定证明时记 NOT_VERIFIABLE。

先核已有直接证据是否覆盖当前对象；依赖未变才能引用。新增结果必须独立审查，b1/r1/r2 的科学结果 NA 永不能继承到 c1。历史动作发生前的状态、执行时身份和用户决定，不能靠事后生成日志或当前 hash 补造。

合同中的阶段 NA、用户豁免、待补和本轮范围排除分别呈现。缺数据不等于不适用。范围排除可以让本轮修复继续，但不能删除完整门的必需项；工具必须同时报告本轮范围状态与整门是否具备完成条件。

**门 B PASS**：独立 Reviewer 的 B1–B4 均通过或有合同依据的 NA，全部最终必需验收与实际产物齐全，无开放阻塞/科学未决，非阻塞项有 owner，机械核验通过，固定提交与全部对象绑定。缺一项不得生成整门 PASS。

## §6 预检、执行与失败处理

按成本由低到高执行：

1. 静态核合同、角色数量、阶段、必需覆盖、字段、路径形状、权限、diff、固定提交及输出唯一性；非法即停，内容哈希和目录巡检不启动。
2. 在实际执行主机核路径、轻量表头/键、依赖导入和授权环境；校验输入供应方式、输出目录创建者、每作业独占目标及消费者接口。不得用本地 stub 代替真实主机可达性检查。
3. 仅对实际消费输入核内容身份。所有常量和派发摘要由权威清单程序生成；已有冻结摘要不因当前不符而更新。
4. 执行时保留实际 argv、cwd、主机、起止时间、退出码、环境、输入/代码/输出身份和原始 stdout/stderr。执行步骤只能引用 manifest 明确的命令和输入；失败、中断记录仍保留，退出码不被 tee 或后续 echo 吞掉。
5. 记录阶段、已处理对象数、字节和耗时。沿用工作区调度器 early runtime 与后续检查频率；未确认启动成功前不长时间 sleep 猜进度。

输出独占创建，目录创建责任只有一处。runner 的证据目录与科学产物目录分开；科学命令须与合同约定的预留/创建模型一致。新 attempt 不复用、不清空，不覆盖失败输出。科学输入、历史日志和旧产物只读。

已授权工程范围内的 flag、环境、路径、供应或接口修复可以留痕处理，但不得改变科学语义、吞掉已产出的科学差异或用旧 PASS 声称新字节已审。正式审查 FAIL 须在本阶段增量修复预算内重审后放行；运行中窄工具修复记录 before/after、失败和回归，并进入下一次独立审查。

纯派发格式/身份错误修正不计实质审查轮次；不允许据此跳过科学阻塞。实质审查完成即消耗该轮，待决事项不会重置预算。无阻塞且验收全部满足应通过，不为凑轮次反复审查。

## §7 内容身份、目录保护与保全

- 实际消费对象按 SHA256 核身份。小型代码、合同、候选、控制文件核当前字节及固定提交；大输入按阶段消费面核验，不因出现在全量 spec 清单就每轮遍历。
- 可流式处理的大输入在同次读取中完成内容摘要与科学检查；证据记录所消费字节及 EOF 完成情况。Reviewer 独立复核使用其自己的实测证据，不能把执行者自报摘要当独立复算。
- 同次调用可去重相同对象；没有可信不可变保障时不跨运行继承旧内容核验。大小/时间相同不证明内容相同。
- content 与 metadata 快照显式区分。metadata 只检查路径、类型、大小、时间、权限和链接目标，不读普通文件内容，也不证明字节相同。旧快照、迁移前后边界与已知差异保留。
- 纯禁写目录使用显式巡检计划。混合目录的保护策略来自冻结授权：历史文件修改/删除失败；获准候选只接受对应 diff 和新字节；允许新 attempt 的路径必须原先不存在、独占创建且未覆盖历史。新增权限不能吸收未解释的既有差异。
- 禁止发现差异后刷新基线消除红灯。范围、排除条件、主机和路径都必须进入计划，检查前认证计划与基线字节；用同一份认证内容进行解析，避免再次按路径读取替换内容。

包内仅保留一套当前实现及回归测试，按功能分模块；历史实现由 Git 保留，新链由 science.py 加载。原项目的冻结脚本、spec 与报告不改写；任何调用的实际依赖均须登记。

## §8 工件与工具

统一入口：`scripts/science.py`；schema 见 workflow-schema.md。底层由 `scripts/workflow.py`、`scripts/verify_digests.py`、`scripts/snapshots.py` 和 `scripts/digest_table.py` 分别处理工作流、摘要核验、目录巡检及表格/Git 解析。新链不能直接绕过统一入口的报告合同检查。

| 工件 | 内容与规则 |
|---|---|
| 验收合同 | spec/有效修订身份、必需要求全集、阶段例外、输入语义、验收与禁止事项；门 A 独立确认 |
| 阶段 manifest | 角色、对象/依赖、命令、预期与实际产物、权限、检查映射、前序许可和巡检计划；不包含自身摘要 |
| 运行记录 receipt | 明确步骤的原始命令、时间、主机、rc、日志和产物身份；不是不可变第三方执行锚 |
| dispatch | 从 manifest 确定性生成，中性描述，不包含作者倾向；不得覆盖前轮 |
| review | 独立报告正文与结构化判定；原始复算输出有真实保存位置，不以摘要冒充 |
| ledger | 唯一动态账本，只追加状态、裁定与有效 PASS；不复制另一套运行状态数据库 |

| 动作 | 职责 |
|---|---|
| render | 生成派发、输入表、实现映射和启动材料；待生成产物标 planned，不造摘要 |
| check | 校验独立合同全集、角色/阶段/依赖/权限/覆盖，再做声明范围身份与巡检；不产生科学 PASS |
| run | 执行明确步骤、独占保存原始证据并传播退出码；不自行决定下一科学动作 |
| record | 按独立 Reviewer 判定及证据生成追加片段；执行前只记许可，缺必需项不得生成整门 PASS |

`g_decision_coverage.py` 继续核上游决定状态与落点；科学验收覆盖使用独立合同，不让两个清单同时删一项产生假绿。

manifest/receipt/报告的生成关系必须无环：不摘要当前自身、不把正在写入的日志当输入、不把本次提交 hash 写入待提交的派发。工具身份核验输出和机器汇总有明确 scope，不能单凭退出码 0 宣告科学完成。

## §9 提交、独立审查与结案

每轮继续两个提交时点：

1. Coordinator 按明确文件列表提交合同/候选/manifest/派发与已有证据（commit①），先核工作区候选，再核固定提交；禁止 `git add -A`。科学数据按原政策 external 保留，不因未跟踪自动豁免身份核验。
2. Reviewer 报告及账本追加内容一起提交（commit②）。未入库报告不能构成正式 PASS。不得 amend/rebase/reset 改写历史审查提交；更正用新文件和新提交。

增量 diff 使用两轮固定 commit 与明确候选 pathspec；Reviewer 独立复算 diff。前序比较基准写入 manifest：执行前修复追溯上次受审候选；结果审查追溯实际放行执行版本及已记录窄修；结果修复追溯上一结果审查版本。只改 evidence 不得虚报候选变化。

启动消息只含角色、已提交的派发路径、完整 commit hash、派发摘要和报告输出路径。Reviewer 先核输入及授权再执行检查；证据不足如实返回，不能要求作者的解释代替直接证据。

完整 PASS 表由工具按已审对象生成，不允许手写“见另一表”替代摘要。记录前验证必需覆盖、独立报告、真实产物、全部适用阶段、未决/阻塞以及保全状态。账本不摘要自身。局部修复可记录范围通过和待办，不能把待办移到脚注后称整门完成。

已有账本错误保留原记录，追加更正说明、适用范围及新证据。生成片段不是自动授予 PASS；完整结案仍由独立审查及固定提交建立。对正在由其他 agent 处理的范围，明确 owner 与未闭合项，不读取或修改被用户排除的对象。

## §10 最终 HTML 科学报告

每条新 SCI 链的最终交付必须包括一个对应完整 spec 的 HTML 科学报告。报告面向读者，逐项解释实验目的、实际方法与样本、结果、直观可视化、科学结论与适用边界；审计状态及执行日志作为辅助证据。

门 A 固定报告合同和分析 ID 全集；门 B 生成报告源、数据引用和 HTML。每个分析都有章节，未执行、取消或证据不足的部分保留状态及依据；不能因缺结果删掉章节或缩小完整科学验收。报告完整不等于实验完整。

最终验收固定六项：RPT-COVERAGE（范围完整）、RPT-METHODS（目的和实做准确）、RPT-RESULTS（数字与实际结果一致）、RPT-VISUALS（图表真实可读）、RPT-CONCLUSIONS（结论和边界有证据）、RPT-PROVENANCE（结果及引用可追溯）。在门 B c1/c2/c3 不得以缺材料授权 NA/deferred；受限补证不能据此生成整门 PASS。

脚本核来源身份、唯一键、展示值、图表绑定、章节覆盖和 HTML 与报告源的一致性；科学意义、统计口径、文献支持及结论强度仍由独立 Reviewer 审核。浏览器检查可读性、轴/图例和窄屏布局，不能仅以文件存在或标签计数验收。

模板规定语义内容，不强制统一图型、页长或图数量。默认用包内离线模板，也可在门 A 批准自定义渲染器和等效机械验收。报告自身的字节必须进入最后受审对象；后续改图、改数字或改结论须对受影响部分重新核验。生成本地 HTML 不自动授予公网发布、上传数据或修改稿件的权限。
