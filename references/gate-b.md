# 门 B：按固定合同实施、执行与审结果

先核门 A 的固定 PASS、spec、科学合同及报告合同。依赖变化只重审受影响部分；
未经审查的新科学语义不能靠记账获得执行许可。

## 准备与执行前审查

- 先核真实主机路径、字段、键、环境、输入供应、输出唯一性、no-clobber 和目录创建责任。
- 科学错误反例必须能失败；空表、重复病例凑行数、漏项、不当 NA 和恒真断言不得通过。
- 已批准的工程接口和有限重试留痕处理。遇到会改变样本、方法或结论的选择停受影响步骤。
- b1 及必要的 r1/r2 核实现、验收器和实际入口；最多两轮修复，不能换名字清零。
- 执行前的结果 NA 不传给结果审查。独立 PASS 只覆盖所列代码、依赖、命令和产物路由。

## 执行与证据

明确一条步骤才调用 run；runner 不决定科学流程、不代替调度器，也不是沙箱。
保存原始命令、主机、环境、起止时间、退出码、日志和输出。新 attempt 独占；
失败证据保留，不清空重用。

仅对本阶段实际消费输入核身份。大输入的科学验收器尽量同一遍流式读取完成摘要和科学断言，
记录字节数、EOF 和耗时。通用 runner 的执行前后检查仍会核可变输入，
不要把整棵大目录塞进 manifest 再期待自动去重；需要单次流式核验时，
在门 A 明确专用验收步骤和对象身份策略，独立审查其完整性。

纯保护目录使用明确的 metadata 巡检计划；历史文件、获准候选和新 attempt 分别处理。
发生差异先归因，禁止刷新基线消除失败。

## 结果与 HTML

从最终必需验收全集启动 c1；必要时 c2/c3 各做一次增量复核。
确定性结果表和统计默认全量独立复算，不能只查行数、来源字符串、作业成功或实现自己的参考值。

报告从实际验收结果生成。scripts/report.py 可生成离线 HTML、图表、结果表和来源定位，
也能核出缺分析、错误引用和页面与源数据漂移。图表与结论的科学含义由独立 Reviewer 检查：

- 对象、样本、实际方法、单位、分母、效应方向和不确定性是否准确；
- 页面数字、图表和文本是否一致；结果是否覆盖合同全集；
- 阴性、异常、失败、未执行与证据缺口是否诚实呈现；
- 文献支持的是观察、机制或关联中的哪一层，是否超出来源覆盖；
- 浏览器中是否可读，轴、图例、缩放、键盘和窄屏展示是否正确。

RPT 六项与科学验收一起进入最终独立审查。报告存在或 HTML 机械检查通过不能代替它们。
没有实质数字的审计看板不是最终报告。未执行的分析可以展示其原因，但全链是否能 PASS
仍由完整科学合同和用户已审裁定决定，不能由报告脚本自行豁免。

## 结案与局部补证

science.py record 只生成候选追加片段；独立报告和账本提交后才能建立正式记录。
作者不得为自己填写独立 PASS。范围补证始终保留整链未闭合项，
不修改旧 PASS，不从当前状态虚构历史事实。
