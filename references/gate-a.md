# 门 A：把科学目标变成可执行合同

按 protocol.md 的 A1–A6 核查。决策问题按依赖与影响排序；用户已有裁定写明原始依据，
被替代、撤销和当前有效状态明确。采用既有方法不等于既有结果已经验收。

## 作者交付

1. 正式 spec：每个分析的目的、样本/分组、输入、计算顺序、统计、异常处理、输出与停止条件。
2. 决策落点表：每个当前有效决定连接规范条款；写作或选图等范围外事项标明不转成分析任务。
3. 科学验收源目录：从 spec 逐项导出全部验收及禁止项，保留语义、定位和可击败的错误反例。
4. 工作流合同：完整 ID 集合、阶段适用性、证据对象和角色、键/单位、允许例外与工程授权。
5. HTML 报告合同：冻结本次分析的 ID 全集及展示要求，格式见 report.md；未执行部分也必须呈现。
6. 运行计划：主机、输入供应、环境、输出唯一性、目录创建责任、资源、重试及人工检查点。

上游有可识别编号时使用 g_decision_coverage.py，并提供非零预期计数。
无编号时逐项做语义对照并明确范围；不要生成零决定覆盖的假 PASS。

摘要从明确清单生成，候选是每次交接的受审字节，尚未生成的产物是 planned。
科学语义和验收全集在门 A 固定，阶段 manifest 只能引用。

## 报告在门 A 就确定

报告的结构是“科学问题 → 实际做法 → 可观察结果 → 科学解释与边界”。
每个分析都登记；可视化适用性在报告合同中确定，不因后来缺图改为不适用。
需要按模型、组别、seed、样本或数据来源区分的维度写入科学验收条款。

通用 HTML 检查 ID 固定为 RPT-COVERAGE、RPT-METHODS、RPT-RESULTS、
RPT-VISUALS、RPT-CONCLUSIONS、RPT-PROVENANCE；门 B 合同保留六项，
在 c1/c2/c3 都适用且不授予最终 NA/deferred。
它们只规定报告验收，不能代替本次分析特有的科学检查。

## 独立审查交接

中性派发只包含角色、固定提交、派发路径与摘要、报告输出路径。
Reviewer 核决定语义、事实、授权、验收强度、读写范围和内部一致性，
不要把作者解释或模板存在当作证据。门 A 保持 b1 加至多一次 c1。

门 A 对合同和反例的通过不等于尚未执行的科学计算已通过。
